# 01 星单机能源部件配置与功率平衡

> 2026-10-26，SCS-01-01。本文对应 [`config/components.json`](config/components.json)、[`components.py`](components.py) 和本地 `out/energy_v2_summary.json`。单机目录依据 [`01星遥测大表.xlsx`](../Data/002-三体星/01星遥测大表.xlsx) 的 A 表：D 列“遥测代号”、J 列“正常值”、N 列“所属系统”。数据库测点能取到，不等于电路边界或功率单位都已独立核实。

## 1. 正确的物理账本与现行可观测量

用户补充的供配电方案 5.3.3 明确为**不调节母线 + 六级 S³R 分流**，电池电压钳位母线；光照期优先母线供负载，其次蓄电池充电，满电后多余输出才分流；阴影期由电池供电，光照期短时不足由太阳阵和电池联合供电。“经 PCDU 充电”是控制和配电路径描述，不能推出“蓄电池绕过母线”。设计文字未标明 TMD017 相对于 PCDU 充电支路的电流传感器位置。

因此先在整个供配电系统边界列稳态账本（所有功率均取同一边界、正方向量）：

```text
P_SA_actual_into_power_system + P_battery_discharge
    = P_load + P_battery_charge + P_shunt + P_distribution_and_control_loss + residual
```

若太阳阵、电池、负载电压电流取在不同端口，还须把线路/控制压降计入损耗；暂态另计母线电容储能变化 `dE_bus/dt`。分流与供配电损耗分别为非负物理项，不得用两个不明边界的测点差额直接冒充。仅在连接图确认 TMD017 位于充电支路上游且覆盖该支路后，才可用 `TMD016×TMD017` 作为母线太阳阵总输入来拆母线账本；若充电支路在测点之前分出，该测点不含充电输入。

**分工况守恒式（公共母线边界）：**各式中的功率取同一时刻、同一边界，`P_load_all` 是全部负载而非未经核实的 `TMD018` 单点；`P_B_ch_bus`/`P_B_dis_bus` 是充放电支路**母线侧**功率，均按非负幅值记账。`dE_bus/dt` 正值表示母线电容等储能增加。

```text
地影：       P_电池放电,母线侧 = P_全部负载 + P_其他 + dE_母线/dt
光照且充电： P_SA_node = P_load_all + P_B_ch_bus + P_bus_loss + dE_bus/dt
光照联合供电：P_SA_node + P_B_dis_bus = P_load_all + P_bus_loss + dE_bus/dt
阵列/S³R：  P_SA_actual_preS3R = P_SA_node + P_shunt_actual + P_S3R_loss
```

地影式暂用 `P_其他` 汇总未分解的收支项，不预先认定为母线损耗或热控功率。`P_全部负载` 应含热控等所有负载，但现有 `TMD018` 的覆盖范围尚未核实；因此不能把电池端试算减 `TMD018` 功率直接当作 `P_其他` 的已测值。`P_B_ch_bus = P_B_ch_terminal + P_charge_path_loss`，`P_B_dis_bus = P_B_dis_terminal − P_discharge_path_loss`。将同一连续有效工况时段的各功率积分，可得对应的能量守恒式，例如地影 `E_电池放电,母线侧 = E_全部负载 + E_其他 + ΔE_母线`、光照充电 `E_SA_node = E_load_all + E_B_ch_bus + E_bus_loss + ΔE_bus`；长缺口不外推。当前阵列电压测点异常且电池/充电支路测点边界未核，以上是暂定账本，不是已算出的闭合结果。

`P_array_S3R_loss_total` 不是整星所有损耗之和；母线配电与线缆、各单机内部损耗属于其他边界。若负载在单机输入端计量，单机内部耗散已经包含在负载功率中，不能在整星电功率账本再加一次。被分流控制抑制、未成为实际阵列电输出的潜在发电功率，也不能直接算作 S3R 发热。

`P_SA_actual_before_shunt` 必须是选定分流节点前**实际产生并流入电路的电功率**。按光照或最大功率点估算的 `P_SA_available` 是潜在能力；S3R 分流可能改变阵列工作点，潜在功率与实际电输出的差额也不一定全部耗散在分流器上，因此不能直接把 `P_SA_available` 代入上述守恒式。

现行整星内核中的历史字段 `P_solar=TMD016×TMD017` 先解释为**TMD017 测点折算功率**，`P_load=TMD016×TMD018` 是负载主测点折算功率。`P_charge_est=max(P_solar−P_load,0)` 和 `P_disch_est=min(P_solar−P_load,0)` 是同一差额的正负拆分；其零残差只是一条代数恒等式，不能验证物理平衡，也不能把 `P_solar` 当作分流前太阳阵总输出。`I_负载−I_TMD017` 只用于测点冲突诊断，不再给 TMH025 判向；差额幅值也不是电池支路电流。

六组 `TMD003–008 × TMD010–015` 给出**帆板端测点 V×I 之和**，另有 `TMD016×TMD017` 测点折算值。代码已计算二者之差 `P_panel_terminal_to_bus_difference_W`：当前扩展分钟输入在 3,495 个观测分钟有完整六组帆板值，其中日照 610 分钟，日照差额中位 25.13 W；全部有效分钟中有 3 分钟差额为负。它是可以逐分钟查看的**测点差额**，不是阵列/S3R 总耗散；若充电支路在 TMD017 测点前分出，差额还可能包含电池充电输入。须确认六组帆板测点处于分流节点前、覆盖全部相关支路，并确认 TMD017、充电分支及采样同步关系。`TMD009−TMD017` 乘母线电压也是边界差异诊断；S3R 档位 `TMD072_b0b3` 与强制分流继电器 `TMD074_b0` 只提供控制/状态信息。

蓄电池电压 `TMD019` 已在当前输入中。《01星遥测大表.xlsx》A 表第 842 行列有“蓄电池组母线电流检测”`TMU146`，第 2640 行另列同名 `TMH025`，没有分开的充电电流和放电电流；两者属于不同遥测链，系数分别为 `/0.0000762939/0/` 和 `1/0/`。用户已确认 CH 的 `TMH025` 是蓄电池母线电流、单位 A，并确认 `TMD074_b1=通` 表示放电。现行整星分钟输入和 06:03 局部图均按 `TMH025_signed_switch=+|TMH025.value|` 给“通”状态赋放电正号；“断”、同分钟切换、缺测或异常原值不赋号，也不自动判为充电。该符号是用户规则派生，不是 CH 原生方向编码。电池电流工程值及与电压测点的端口位置仍需核对，不能直接把局部试算代入母线损耗公式。若测点实为电池端，电池到母线的变换和线缆损耗仍须归边界；用现行差额推算的 `P_charge_est/P_disch_est` 代回母线式会人为令损耗为零。`physical_balance.status=unavailable`。

## 2. 可装配部件接口

每颗卫星用一个配置目录装配单机，目录含 `telemetry_params.json`、`design_params.json`、`v_soc_curve.json`、`components.json`。取数与评估入口接受 `--profile-dir`，在同一进程中再次调用也会重新读取该卫星的部件配置。`components.json` 每项有稳定 `id`、`role`、`plugin` 和显式 `enabled`；禁用项既不取数也不参与计算。当前内置插件：

| 模型 | 计算或输出 | 使用条件 |
|---|---|
| `vi` | 独立电压 × 独立电流 | 同一单机/支路且单位已核对 |
| `bus_current` | 母线电压 × 支路电流 | 仅称“母线等效功率”，支路真实电压待核 |
| `power` | 独立功率遥测 | 须明确 `unit=W`，并核实正方向与测量边界 |
| `state` | 状态、利用率、电压等上下文 | 不加入负载求和；不把状态当功率 |

现行代码的角色覆盖 `solar_array`、`solar_available`、`solar_pre_shunt_actual`、`load`、`battery_charge`、`battery_discharge`、`shunt`、`loss` 和 `context`。其中 `solar_array` 在当前配置中仅代表**板端测点输出**；`solar_available` 是保留但不参与物理闭合的历史命名，不能接入最大功率点等潜在能力估算值来宣称闭合。闭合输入必须使用 `solar_pre_shunt_actual` 并核实完整边界。当前配置的 `balance_boundary_verified` 明确为 `false`。

插件实例是卫星配置中的一项单机；同一个 `vi` 或 `bus_current` 插件可以装配到不同的单机和卫星。特殊单机可在受信任的本地 Python 模块中调用 `register_plugin(name, ComponentPlugin(...))`，并将模块名列入该卫星 `components.json` 的 `plugin_modules`；装配器导入模块后按每项 `plugin` 选择计算器。插件声明必需测点、功率口径、是否使用母线电压和是否仅提供状态，计算函数须返回与输入时间轴相同的 W 序列。旧配置的 `model` 字段仍可读取。插件模块是可执行代码，只加载本地可信模块；跨星需要核对测点单位、正方向和供电边界，不能仅凭同名遥测复用功率解释。

状态工况使用数据库 `value_str`。同一分钟若出现多个状态文字，标记“分钟内切换”；没有同分钟状态则标“缺测”，不向前填充。单机数值缺测或负的无符号电流/电压保持空值，不按零参与求和。整星时间轴取五个核心电源测点观测分钟的并集；仅有单机状态、没有核心电源测点的分钟不会虚增整星观测时长，核心太阳阵电流缺测的分钟保持工况未判定。单机 `V×I` 是**电压分钟均值 × 电流分钟均值**，尚未验证逐采样同步乘积。原始采样积分仍只用五个核心电源测点；单机当前输出是**逐观测分钟功率代理/状态**，不是连续全期耗能。

## 4. 真实数据复算与边界

本次补采仍按星上北京时间 `[2025-12-26, 2026-08-12)`、卫星 `SCS-01-01` 和 7 天有界批次。生产长表中数值电流保存在 `value`，枚举状态保存在 `value_str`；此前 `value IS NOT NULL` 会漏掉后者。新版分钟数据请求 119 个代码、得到 2,260,014 个“分钟×代码”记录，清单哈希为 `2cbd229b4eda0b94fcbf77fda46022309475b8aaae6f2512db960a4ab18afd3c`。主时间轴仍有 19,727 个整星观测分钟，日照/地影/未判定 12,993/6,517/217；核心评分 94 仅针对观测样本。旧五项电源分钟文件的 414,267 个记录与新版对应记录在时间、代号、计数和全部数值统计列一致；新版补齐了部分 `param_name`。两次复算的 `metrics`、`phase`、`interval_energy`、`health` 全部相同。原始间隔积分的日照 TMD017 测点折算/负载仍为 29.595/11.916 kWh；前者不能在测点拓扑未核实时称为太阳阵总输出。

94 个已启用槽位中，6 个板端功率、25 个负载支路功率、63 个状态/电压上下文。科学载荷的 `TMX020×TMX021` 在 15,463 个整星观测分钟上有效，按 `TMX026` 的同分钟状态分组得到：

|---|---:|---:|---|
| 上电未配置 | 14,129 | 2.24 | 已上电，并非零功耗 |
| 预掉电 | 1,145 | 2.70 | 同分钟 V×I 均值 |

| 分钟内切换 | 5 | 3.61 | 不归到某一稳定模式 |

10G 激光模式在主时间轴上“休眠”9,394 分钟、缺测 10,332 分钟；100G 激光“休眠”15,058 分钟、“待机”40 分钟、缺测 4,629 分钟。这些模式尚未和激光处理机 1/2 的供电支路建立已验证映射，因此不发布“通信模式功耗”。强制分流继电器在 19,726 个分钟为“禁止”、1 个分钟内切换；这不能推出 S3R 自动分流为零。

25 路负载支路在同一分钟**全部数值有效**的仅 953 分钟；其中 897 分钟支路 V×I 和大于 `TMD018×TMD016`。`P_load_minus_branch_sum_W` 保留有符号差额，不能称“剩余负载”或“损耗”，也不能用支路和替代整星负载评分。优先核对 TMD018 的覆盖边界、各 PCDU 支路电压、CXPD/科学载荷是否重叠以及负值/零点标定。板端六组 V×I 同时有效仅 3,495 分钟，不能据此形成完整分流前太阳阵可用功率序列。

## 5. 复现与下一步测量

已授权的本地明文连接例外下，可在 `ResearchSpace` 运行：

```powershell
$env:CH_ALLOW_PLAINTEXT='1'
python s1_fetch.py --transport http --start 2025-12-26 --end 2026-08-12 --source-timezone Asia/Shanghai --out out/data_power_minute_components.csv
python s3_run.py --data out/data_power_minute_components.csv --raw-data data_power_raw.csv --out out
python gen_charts.py
```

主结果是 `out/energy_v2_components.csv`（每个主观测分钟的单机功率、工况和差额诊断）、`out/energy_v2_summary.json` 的 `components` 段及 `framework_documentation_current.html` 的单机表和可选择显示的功率曲线。曲线只绘制有支路电流或电压/电流对、可计算功率代理的负载单机，在所选整星观测窗口中缺测断线；仅有支路电流时是母线等效功率。整星图表的“帆板端与 TMD017 测点差额”只画明确日照且六组帆板测点完整的分钟，缺测不填零；充电支路位置未核，不能称其为 S³R 总耗散。母线损耗暂无数值曲线。单机曲线与整星遥测图表各有一个显示区域，通过各自的选择器切换；整星图表单位不同，不共用纵轴。不把状态型加热器画成耗电功率，也不将分钟功率代理称为实际电量。两份来源清单与配置/代码 SHA-256 一并进入摘要。跨星时复制并修改整个配置目录，三个脚本传相同 `--profile-dir`，输出至独立目录；当前取数器仍要求相同长表字段及 `onboard_time_bj` 的北京时间语义。

要得到可检验的分流与单机能量闭合，还需：明确分流节点前实际电输出及阵列控制边界、电池支路独立电流及其符号、分流支路实际电功率和 PCU 损耗测量；另需各单机供电拓扑、支路电压与状态码的同步关系。取得后用 `solar_pre_shunt_actual` 角色及同一时间轴验证残差与不确定度。
